# Contributing to Tessera

Thank you for helping. Please read the required documents before your first contribution.

## Required reading

1. **[docs/CLEAN_ROOM.md](docs/CLEAN_ROOM.md)**: the dirty and clean zones, roles, the spec
   lifecycle, AI-assistance rules, commit trailers, and the **clean-room attestation**
   (§9) that you agree to by signing off.
2. **[DISCLAIMER.md](DISCLAIMER.md)**: the non-affiliation statement.
3. **[CLAUDE.md](CLAUDE.md)**: the short form of the rules, also used by AI agents.

## Pick your role

Every contribution is either a **spec** (research, written in `docs/specs/`), a **review**
of a spec, or an **implementation** (code in `crates/`, `apps/`, `fuzz/`, `tools/`). For any
one subsystem you are a spec writer **or** an implementer, never both. If you have read
`research/`, third-party LOTRO/DDO/Asheron's Call source, or any disassembly for a
subsystem, you may not implement that subsystem.

Implementers: if a spec lacks a fact you need, add a `> **OPEN:**` question to the spec and
stop. Do not look the fact up elsewhere.

## Hard rules

- **No game data in the repository**: no `.dat`/`.datx`, extracted textures, meshes, sounds,
  text, maps, databases, Lua UI files, fonts, binaries or keys. Tests use synthetic fixtures
  generated by our own code, or original CC0 content.
- **Never write to a game install.** Real-data tests read `TESSERA_GAME_DIR` and are skipped
  when it is unset.
- **No code from other LOTRO tools**, whatever their licence. Facts go into a spec;
  code is written fresh.
- **No decompiler or disassembler output**, ever, in code or in a session that writes code.
- **Official-server connectivity (M8) rules** ([decision 0034](docs/decisions/0034-official-server-compatibility.md)):
  - No shipping, mirroring or linking to client binaries, dat files, patches or old clients;
    no modified, patched, redirected or injected official client; no Daybreak keys or other
    secrets in the repository, releases or documentation; no committed captures from official
    servers; no leaked, NDA-covered or decompiled vendor source; no bypassed authentication,
    subscription check, anti-cheat or other access control.
  - No Daybreak hostnames or endpoints in the repository: the client reads them at runtime
    from the user's install.
  - Live logins never run from CI.
- **No trademarks in names.** See [CLAUDE.md](CLAUDE.md#naming).

## Commits

Every commit is signed off under the [Developer Certificate of Origin 1.1](https://developercertificate.org/)
(`git commit -s`), which also confirms the clean-room attestation. Add these trailers when they
apply (details in [CLEAN_ROOM.md §8](docs/CLEAN_ROOM.md#8-commit-trailers)):

```
Spec-Ref: docs/specs/<file>.md#<anchor>     # format/protocol/algorithm code
Clean-Room-Role: spec | review | implementation
Assisted-by: <tool>:<model>                  # any AI assistance
Signed-off-by: Your Name <you@example.org>
```

Pseudonyms are accepted if you use the same one consistently.

## Code checks

- Rust edition 2024; toolchain from `rust-toolchain.toml`.
- Before pushing:
  ```
  cargo fmt --all
  cargo clippy --workspace --all-targets -- -D warnings
  cargo test --workspace
  ```
- Every source file starts with <!-- REUSE-IgnoreStart -->`// SPDX-License-Identifier: GPL-3.0-or-later`<!-- REUSE-IgnoreEnd -->.
- Parsers treat input as hostile: no panics, bounded allocations, `thiserror` errors, and a
  fuzz target in `fuzz/`.
- Library crates log with `tracing`, never `println!`.
